## What this is

Static HTML/CSS/JS personal portfolio for Aoy Phongsakoun. No build system, no npm, no compilation step. All pages are plain HTML files served as-is.

## Local development

```bash
# Run from the repo root
python3 -m http.server 8080
```

Open `http://localhost:8080`. Must use a local server (not `file://`) — `fetch()` calls for JSON data will fail otherwise.

## Adding or editing blog posts

All blog content is authored in JSON, not HTML.

**1. Edit `blogs/data.json`** — add a new object to the array, or edit an existing one. Each post requires:
- `id` — unique kebab-case slug (URL-safe, lowercase)
- `tag`, `title`, `excerpt`, `date` (YYYY-MM-DD), `readTime`
- `cover` — HTTPS Cloudinary URL
- `images[]` — gallery URLs (include cover as first entry)
- `sections[]` — array of `{ "title", "body" }` objects; this is the article body

**2. Update `blogs/preview.json`** — lightweight copy used for the homepage cards. Contains `total` (full count from data.json) and `preview` array (4–5 posts, no `sections` field needed).

**3. Regenerate static share pages** (needed for Facebook/LinkedIn OG previews):
```bash
node scripts/generate-blog-share-pages.mjs
```
This writes `post/{id}/index.html` for every post in data.json. Run after any cover URL or title change too.

**Validate JSON:**
```bash
python3 -m json.tool blogs/data.json > /dev/null && echo "OK"
```

See `blogs/BLOG_JSON_AI_PROMPT.md` for an AI prompt template to generate new blog post JSON.

## Architecture

### Pages
- `index.html` — main portfolio (hero, experience, projects, education, blog preview, contact)
- `blogs.html` — blog listing and single-article reader (URL: `blogs.html?id={slug}`)
- `activities.html` — activities/events listing

### Data layer
- `blogs/data.json` — all blog posts with full `sections[]` content
- `blogs/preview.json` — homepage preview: `{ total, preview: [...] }` (no sections)
- `events/data.json` / `events/preview.json` — same pattern for activities

### JavaScript
- `js/blogs.js` — entire blog system: fetches JSON, renders cards, handles modal, renders single-article view. Configured via `window.__BLOGS_CONFIG__` set inline in the HTML before the script.
- `js/events.js` — activities card rendering (same pattern as blogs.js)
- `js/blog-social-meta.js` — updates `<meta og:*>` tags client-side when reading `blogs.html?id=...`
- `js/grid-skeleton.js` — skeleton loading placeholders shown while JSON fetches
- `js/site-cv.js` — CV download modal
- `js/site-nav.js` — nav highlight and scroll behavior
- `js/custom-cursor.js` — custom cursor (desktop only; disabled inside CV modal)
- `js/image-loading.js` — lazy image fade-in

### Styling
- `styles/main.css` — global styles and index page
- `styles/cv-modal.css` — CV modal overlay
- `css/blogs-page.css` — blog listing page
- `css/blog-article-ui.css` — article reader and all `:::` component styles
- `css/activities-page.css` — activities page
- `css/subpage.css` — shared subpage shell (header/footer)
- `css/grid-skeleton.css` — skeleton animation
- `css/content-meta.css` — date/readTime meta chip styles
- `css/custom-cursor.css` — custom cursor

### Section body renderer (in `js/blogs.js`)
Blog `sections[].body` is plain text with lightweight Markdown-like syntax. The renderer in `js/blogs.js` → `renderBodyHtml()` supports:

| Syntax | Renders as |
|--------|-----------|
| ` ```lang ... ``` ` | Syntax-highlighted code block with Copy button |
| `**text**` | Bold |
| `` `code` `` | Inline code |
| `- item` lines | Bullet list |
| `:::callout tip\n...\n:::` | Tip/warning callout box |
| `:::compare\nA\|desc\nB\|desc\n:::` | Two-column compare cards |
| `:::reminders\nLabel\|desc\n:::` | Numbered reminder items |
| `:::defs\nTerm\|desc\n:::` | Definition list |
| `:::steps\n1) ...\n:::` | Ordered steps |
| `:::analogy\n...\n:::` | Analogy callout with bullet list |
| `:::table\n\| Col \| Col \|\n:::` | Markdown table |
| `:::arch mvc:::` / `:::arch mvvm:::` / `:::arch dual:::` | Architecture diagram SVG |
| `Credit: ...` paragraph | Styled credit line |

Supported fence languages: `python`, `bash`/`sh`/`shell`, `dart`, `sql`, `dockerfile`, `javascript`/`js`, `json`, `html`, `powershell`, `yaml`/`yml`.

### Social sharing / OG tags
Two mechanisms handle Open Graph for blog posts:
1. **Static share pages** (`/post/{id}/index.html`) — generated by `scripts/generate-blog-share-pages.mjs`; used for social sharing links
2. **Cloudflare Pages middleware** (`functions/_middleware.js`) — server-side OG injection for `blogs.html?id=...` when deployed to Cloudflare Pages (not needed on GitHub Pages)

Share URL format: `https://aoypsk8.github.io/aoy-portfolio/post/{id}/`  
Reader URL format: `blogs.html?id={id}` (not shareable to social apps)

### Deployment
- **GitHub Pages**: primary deployment at `https://aoypsk8.github.io/aoy-portfolio/`
- **Cloudflare Pages**: optional; uses `wrangler.jsonc` and `functions/_middleware.js` for dynamic OG injection
- Cover images hosted on Cloudinary (`res.cloudinary.com/duswpvmeh`)
